# logq Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A host-side Python CLI, `logq`, that gives Claude filtered, redacted, time-ordered logs across a compose project's containers, plus a `docker-logs` skill and a logging contract document.

**Architecture:** `logq` shells out to the `docker` CLI (current context) to list, inspect and read containers. Lines flow parse → filter → render. `query` prints a snapshot; `follow` runs reader threads and `docker events` into one queue for Claude Code's Monitor.

**Tech Stack:** Python ≥ 3.11 standard library, pytest (dev only), hatchling build backend, `uv`.

**Spec:** `docs/superpowers/specs/2026-11-07-logq-design.md`

## Global Constraints

- Runtime dependencies: none. `pytest>=8` in the `dev` dependency group only.
- Docker access only through the `docker` CLI, never the SDK or the raw socket. Never pass `--context`; the active context is used.
- Defaults: window `15m`, limit `50`, message cut at 300 characters, per-container read cap 50,000 lines, repeat window 30 s, trace IDs shown as 8 characters, `--trace` needs at least 8 characters.
- Level scale: `debug=10, info=20, warn=30, error=40, fatal=50`. `query` and `follow` default to `warn`, or `debug` when `--trace` is given.
- Display times in the system's local zone (America/Chicago here), format `HH:MM:SS.mmm`. Functions take a `tz` argument so tests are deterministic.
- Redaction applies to every printed line, including `--full`, and cannot be turned off.
- Exit codes: `0` success (including no matches), `1` usage error or unknown project, `2` Docker unreachable.
- Event line layout: `time service LEVEL [method route status duration] [func] body [trace=xxxxxxxx]`, trace last.
- Tests run with plain `uv run pytest`, single process.
- Jaeger (Tasks 10–12): container `logq-jaeger`, image `cr.jaegertracing.io/jaegertracing/jaeger:2.23.0`, ports published on `127.0.0.1` only (`16686`, `4318`), MCP at `http://localhost:16686/api/ai/mcp/`. Ask the user before any step that pulls the image or changes Claude's MCP configuration.

## Review Focus

1. `docker compose up` recreates a container while `follow` runs: logq must attach to the new container and show its lines (Task 7).
2. A payload that is valid JSON but not an object (`[1]`, `"s"`, `42`) must be treated as plain text, not crash (Task 1).
3. Dev servers colour their output; ANSI escape codes must be stripped before level inference and display (Task 2).
4. Running from a subfolder of a project nested in another project's folder must pick the deepest matching `working_dir` (Task 4).
5. Containers that print bytes that aren't UTF-8 must not crash `logq`; bad bytes become `�` (Task 8).

- [ ] **Step 4: Implement `split_docker_line` and `parse_payload` in `logq/parse.py`**

- [ ] **Step 4: Implement plain-text inference, `Grouper`, `parse_stream` and frame extraction in `logq/parse.py`**

Strip ANSI with `re.sub(r"\x1b\[[0-9;]*[A-Za-z]", "", s)`. Level rules, in order: an upper-case word matching `\b(TRACE|DEBUG|INFO|WARN|WARNING|ERROR|CRITICAL|FATAL|PANIC)\b` (TRACE→debug, WARNING→warn, CRITICAL/PANIC→fatal); `Traceback (most recent call last):` or `\b[\w.]*(?:Error|Exception):` → error; `\b[\w.]*Warning:` → warn; otherwise info. Grouping rules are in spec §5.2. Error summary for plain text: the line that ends a Python traceback, else the first line when it matches the error pattern. Frames: Python takes the last `File "(.+)", line (\d+), in (\S+)` as `path:line in func`; JS and Java take the text after `at ` on the first line starting with whitespace + `at `.

- [ ] **Step 4: Implement `logq/docker.py`**

- **Pseudo-projects:** containers without the compose project label get the container name as both project and service.
- **`list_containers`:** raises `DockerUnreachable` on `FileNotFoundError` or a non-zero exit from `docker ps`. The context name comes from `docker context show` (fall back to `"default"`), and the detail is the first stderr line.
- **`read_logs`:** runs `docker logs --timestamps --since S [--until U] --tail <cap> <id>` with stderr merged into stdout. `capped` is `len(lines) == cap`. On a non-zero exit, `error` is the first line `split_docker_line` rejects, and the timestamped lines are kept.
- **`follow_logs`:** runs `docker logs -f --timestamps --tail 0 <id>`.
- **`events`:** runs `docker events --format '{{json .}}' --filter type=container`. For `all` it adds nothing, for pseudo-projects `--filter container=<project>`, and otherwise `--filter label=com.docker.compose.project=<project>`.
- **`parse_since`:** accepts `^\d+[smh]$` or a value `datetime.fromisoformat` accepts.

- **Repeat key:** `(container, level, re.sub(r"0x[0-9a-fA-F]+|[0-9a-fA-F]{8,}|\d+", "#", error or msg))`.

- **Shutdown:** a SIGTERM handler raises `SystemExit`, and a `finally` block terminates every child process.
